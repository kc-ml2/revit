Reproduction commands and scope
Run from the repository root: revit_optim/revit

1. Environment

Install the repository requirements in a Python environment with torch and
torchvision builds appropriate for the target device. requirements-dev.txt
adds pytest. The measurements here used Python 3.12.14, PyTorch 2.9.1,
torchvision 0.24.1, ESCNN 1.0.11 and NumPy 1.26.4 on macOS arm64 CPU.
Exact recorded versions are in environment.json. No CUDA was available.

This local .venv is intentionally ignored by Git. ESCNN's optional py3nj
was omitted for these finite-2D tests; it only changes the unused SO(3)
coefficient fallback. lie_learn was installed from the repository's requested
Git source. Its built wheel omitted required bundled .npy files, so the test
environment uses an editable source checkout in .venv/lie_learn-src. This
environment workaround is not a modification to the model or dependency
sources tracked by this repository. If necessary on a similar machine:

  python -m pip install Cython setuptools wheel "numpy<2"
  git clone https://github.com/AMLab-Amsterdam/lie_learn.git .venv/lie_learn-src
  python -m pip install --no-build-isolation -e .venv/lie_learn-src

Use python=.venv/bin/python when reproducing with the local test environment.

2. Regression tests

  python -m pytest -q --tb=short

The suite includes genuine two-process Gloo tests requiring local loopback
network access. An execution sandbox can block these even with a file-based
rendezvous; allow local loopback or use an unrestricted test environment.

3. Main parameter and FLOP sweep

  python scripts/profile_scaling.py --model-sizes tiny small base large \
    --groups C4 D4 --image-sizes 224 448 --kernel-sizes 1 3 \
    --exact-parameters --output analysis/scaling_results.json

  python scripts/profile_scaling.py --model-sizes tiny \
    --groups Z2 D2 C8 D8 --image-sizes 224 --kernel-sizes 1 3 \
    --exact-parameters --output analysis/group_scaling_results.json

  python scripts/profile_scaling.py --basis-output analysis/kernel_basis_dimensions.json

Omit --exact-parameters for dependency-free dense arithmetic estimates.
It avoids constructing very large expanded kernels for large groups/models.
--basis-output needs ESCNN but builds only single-field kernels.

To vary geometry, pass --window-sizes, --image-sizes and --stem-downsample.
geometry_scaling_results.json records estimate_revit(MODEL_PRESETS['small'],
8, image_size, window_size, 3, 4, stem_downsample) for the Cartesian product
image_size=(224,320,448), window_size=(4,7,14), stem_downsample=(2,4,8).
These are sensitivity estimates, not recommended replacement architectures.

4. Original-versus-revised CPU measurements

  python scripts/benchmark_optimizations.py --baseline-ref 2558962 \
    --model-size tiny --group D4 --qkv-kernel-size 3 \
    --output analysis/cpu_benchmark.json

  python scripts/benchmark_optimizations.py --baseline-ref 2558962 \
    --model-size tiny --group C4 --qkv-kernel-size 1 \
    --output analysis/cpu_benchmark_c4_k1.json

The original source is read using git show and loaded from a temporary file;
the working tree is not reset or changed. Both models use identical copied
weights and start with the same BN state for numerical comparisons.
Results include per-iteration samples, medians, configuration, environment,
max logit differences and full-model 90-degree invariance discrepancies.
Constructor timing is cold-first/warm-second and is not an isolated benchmark.

For target-hardware measurements, add --device cuda --dtype float16 (or
bfloat16) --batch-size N. Use sufficient iterations and your actual training
batch size. Peak allocated CUDA bytes are recorded on CUDA; CPU memory
fields are null. The benchmark excludes optimizer/data loading and uses
dropout/stochastic depth=0 so deterministic numerical checks are meaningful.

5. End-to-end smoke training and resume

The saved smoke logs use /tmp/revit_imagenet_smoke with train/val subfolders,
two class folders per split and two 72x72 RGB PNGs in each class folder.
The images were constant colors (30+40*class, 60+20*index, 100). This has no
relationship to ImageNet accuracy; its purpose is exercising the pipeline.

  python imagenet_train_revit.py \
    --data-root /tmp/revit_imagenet_smoke --output-dir /tmp/revit_train_smoke \
    --epochs 2 --warmup-epochs 0 --batch-size 2 --num-workers 0 \
    --dims 2 4 4 8 --depths 1 1 1 1 --heads 1 2 2 4 \
    --image-size 64 --window-size 2 --num-classes 2 --group-str D4 \
    --qkv-kernel-size 3 --use-checkpoint --no-randaugment \
    --checkpoint-interval 1 --log-interval 0

Repeat with the same options, change output-dir to /tmp/revit_resume_smoke
and add:
  --pretrained --pretrained-path /tmp/revit_train_smoke/checkpoints/best.pt

For this run the best checkpoint is epoch 0. The resumed run executes only
epoch 1, stopping at the total target 2. Every model state tensor in the two
last.pt checkpoints matched exactly; scheduler states matched too. The
comparison and configuration are stored in smoke_resume_results.json.

6. Full ImageNet training

Use the README's existing single-GPU/torchrun commands and record all
configuration values. Preserve the chosen group, field counts, depths,
QKV kernel, image/window sizes, effective batch size and LR schedule when
testing execution-only changes. Default fused QKV can be disabled with
--no-fused-qkv. SDPA, BF16 and fused AdamW are opt-in comparisons.

The supplied measurements do not establish CUDA throughput, distributed
NCCL performance or full ImageNet accuracy. The code changes are complete
and locally verified; a dataset/hardware training campaign is the remaining
empirical accuracy validation described in OPTIMIZATION_REPORT.txt.
